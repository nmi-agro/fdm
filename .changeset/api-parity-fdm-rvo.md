Add `applyRvoImport`, which saves a reviewed field import (fields to add, update and remove) in one transaction, and the building blocks of a two-step import: `reviewShapefileImport` (reads a shapefile export and compares it with a farm), `compareShapefileFields` (with the buffer strip estimate for shapefiles), `getAllowedImportActions`, `getReviewHash`, `getImportItemValues` and `resolveImportChoices`, which turns one action per item with optional per-field values into the changes to save. `processRvoImport` now uses the same code: `UPDATE_FROM_REMOTE` only changes the values that differ or are missing locally, `CLOSE_LOCAL` only sets the end date, and a new field without buffer strip information is not a buffer strip. It returns the created, updated, closed and removed fields and throws `ImportChoiceError` when an action does not fit the status of its item. Each review status has one action that changes nothing: `KEEP_LOCAL` for items with a local field and `IGNORE` for new fields from RVO. `processRvoImport` follows the same rule, so `IGNORE` for an item with a local field now throws `ImportChoiceError`; use `KEEP_LOCAL` or `NO_ACTION` instead.
